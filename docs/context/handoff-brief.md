## 2. Rejected approach — and why

He proposed **cyclical keto**: zero carbs on rest days, carbs around training sessions.

**Rejected. `[Certain]` reasoning:** nutritional ketosis takes ~3–4 days at sub-30 g carbs to
establish, and a single carb feed around training breaks it. At 5 training days per week there are
only 2 rest days, so ketosis is never established and glycogen is never fully loaded. The week is
spent in a transition zone that delivers neither benefit.

**Risk named:** glycogen depletion hits hardest in the 8–15 rep range — precisely the volume that
drives hypertrophy. Expect flat sessions, dropped working sets, and misattributed blame to the programme.

**Replaced with carb cycling** (section 3). Do not reopen this unless new information is offered;
"but I really think" is not new information.

## 3. Diet — current plan

Baseline: maintenance estimated ~2,700 kcal/day. Target weekly average ~3,000 (+300 surplus).
Expected rate **+0.2–0.3 kg/week**. Anything faster is fat.

**These are estimates from height, weight and training load — `[Guessing]`, not measurements.
The 14-day bodyweight trend overrides them.**

### Training days (5)
| Macro | Target |
|---|---|
| Calories | ~3,200 kcal |
| Protein | 170 g |
| Carbohydrate | 300 g |
| Fat | 145 g |

Carb placement: ~80–100 g in the meal 2 hours before lifting, ~80–100 g in the meal after,
remainder spread across the day. Sources: rice, potatoes, oats, fruit.

### Rest days (2 — Wednesday and Sunday)
| Macro | Target |
|---|---|
| Calories | ~2,500 kcal |
| Protein | 175 g |
| Carbohydrate | 60 g |
| Fat | 175 g |

60 g, not zero. Sources: vegetables, berries, a little dairy.

### Non-negotiables
- Protein hits **every day**, rest days included.
- Progressive overload logged. If bar numbers don't move month over month, the surplus is wasted.
- Creatine monohydrate 5 g daily. `[Certain]` most evidence-backed supplement for this goal.

### Calibration protocol
1. Weigh daily, same conditions. Average the week.
2. Run the above for 14 days.
3. Weekly average +0.2–0.3 kg → correct. Flat → **add** 200 kcal to training days.
   More than +0.5 kg → **cut** 200 kcal from training days.

### Watch item
`[Likely]` rest-day fat at 175 g is easy to overshoot because fat is calorically dense and hard to
eyeball. Weigh fats for the first two weeks.

### Caveat given
Not a dietitian. Sustained high-fat intake is worth running past a doctor if there is any
cardiovascular or metabolic history.

### Execution rules
- **Power days:** pick a weight you could get one more rep with, not two. Add 2.5 kg when all sets hit the top of the range.
- **Speed work:** submaximal, moved fast, short rest. Not a warm-up, not a burnout set. Never grind.
- **Hypertrophy sets:** 1–2 reps in reserve. The 15–20 rep sets should burn.

### The week 6 test
Are the top sets on **row, bench, squat, deadlift** higher than week 1?
If no: `[Certain]` the split is not the problem and neither is the diet. Either the sets are not
close enough to failure, or he is not eating enough. Fix one, not both, give it three weeks.

## 5. Deliverables built (both complete)

### A. `phat-log.xlsx` — the system of record ✅ chosen
Six tabs. Yellow cells are inputs; everything else is a formula.

| Tab | Purpose |
|---|---|
| **Log** | One row per set. Day and Exercise are dropdowns. Volume auto-calculates. |
| **Bodyweight** | Date + weight. 7-day average, weekly change, and the calorie decision all auto-calculate. |
| **Progress** | Top set per key lift per week, pulled from Log via `_xlfn.MAXIFS`. Start date in `D4`. |
| **Program** | Full PHAT reference with sets, rep ranges, technique cues. |
| **Diet** | Section 3 targets. |
| **Read me** | Legend. |

**Intended home:** Google Drive → File → Save as Google Sheets. Chosen for durability — survives
loss of any chat, reachable from phone and laptop.

**Gotcha `[Certain]`:** Progress matches exercise names *exactly*. Typing "Bent over row" instead of
picking "Bent-over row" from the dropdown silently drops that set from the trend.

**Verified:** recalc clean (2,656 formulas, 0 errors) *and* spot-checked with real data — volume,
weekly top-set resolution, and bodyweight thresholds all return correct values.

### B. `phat-tracker.html` — optional in-gym logger
Single self-contained file. Vanilla JS, no dependencies, no build step.

- Session-first flow: pick day → log sets with ± steppers (2.5 kg / 1 rep), last session's numbers shown inline.
- Overload verdicts: power days flag "+2.5 kg next session" when all sets hit the top of range; hypertrophy days compare total volume.
- Movement diagrams: 15 SVG movement patterns covering all 46 exercise slots, each with a technique cue. Collapsed behind a tap.
- Trend view with the week 6 stall check baked in.
- Bodyweight tab with 7-day average and the calorie decision.
- JSON export.

**Storage `[Certain]`:** uses `window.storage` when running as a Claude artifact (account-scoped,
syncs across devices, tied to that conversation); falls back to `localStorage` when the file is
opened standalone (device-local). These are two separate stores — do not use both.

**Bug history (don't reintroduce):** a helper named `top` collided with the read-only browser global
`window.top` and threw `SyntaxError` before any code ran, rendering a black box. Renamed to `topSet`
and the whole script is now wrapped in an IIFE with `"use strict"`. Any future top-level identifier
must avoid browser globals.
