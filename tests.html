S30 is E-3, the backup client’s pure half — backupPayload, restorePayload, validateSessionDoc, validateBwDoc, backupSig, agoText. The hazard it exists for is that JSONB does not keep key order: a set that went up {w:100,r:5} comes back {r:5,w:100}, and every serialised-JSON assertion in this file would read a restored session as a corrupted one. So the round trip is asserted on JSON.stringify through a simulated Postgres reorder (key length, then bytes, at every depth), and the simulator is itself a GUARD test that must change the bytes before anything leans on it.
